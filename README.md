# OmniNotice E2E Automation (Regression)

Автоматизированные E2E-тесты для платформы **OmniNotice** (админ-панель). Проект покрывает сквозные сценарии регресса (создание и отправка рассылок, валидация, обработка ошибок) и API-контракты.

## 🛠 Стек
*   **Playwright**
*   **TypeScript**
*   **Node.js**

## 📊 Текущее покрытие (UI)
На данный момент **10 UI-тестов проходят успешно**, 5 заскипаны (в ожидании починки фронтенда/бэкенда).
Покрыты следующие блоки:

*   **Happy Path:** Полный сценарий создания и отправки Push-рассылки.
*   **Валидация:** Лимиты полей (заголовок/текст), невалидные URL.
*   **Обработка ошибок (Моки):**
    *   Ошибка 500 (Internal Server Error) — зафиксирован баг с ложным тостом об успехе.
    *   Частичный успех (Partial success) — проверка, что фронт не врет про полный успех.
    *   Ошибка загрузки получателей (Retry).
*   **Модальное окно:** Отмена подтверждения (сохранение формы), текст подтверждения (без слова «писем»).
*   **Преждевременный успех:** Зафиксирован баг (заскипан), когда тост об успехе появляется до ответа сервера.

## 🚫 Заскипанные тесты (Skip)
Следующие тесты написаны, но временно отключены (`.skip`) по объективным причинам:
*   **История рассылок (3 теста):** Раздел временно закрыт на фронтенде. Тесты включаются после открытия.
*   **Telegram (1 тест):** Функционал Telegram-рассылок не реализован (не открывается модалка подтверждения). Тест включается после готовности.
*   **Payload (1 тест):** Перехват запроса (REG-CORE-014). Заскипан, так как стенд работает на моках (реальный запрос не уходит в Network).

## 📊 Текущее покрытие (API)
В папке `tests/api` находятся тесты на контракт, авторизацию и лимиты.
*(Примечание: тесты на идемпотентность отправки временно закомментированы, так как тестовый стенд возвращает 403 от Doocot).*

## 🚀 Как запустить локально

### 1. Установка зависимостей
```bash
npm install
npx playwright install chromium
2. Настройка окружения
Скопируйте .env.example в .env.dev и заполните данные:

bash
cp .env.example .env.dev
В .env.dev укажите:

UI_LOGIN и UI_PASSWORD (данные для входа в OmniNotice)

DELEGATED_TOKEN (для API-тестов)

PROJECT_ID (заголовок Project-Id из DevTools)

3. Запуск тестов
bash
# Запустить только UI-тесты
npm run test:ui

# Запустить только API-тесты
npx playwright test --project=api

# Запустить всё сразу
npm test
4. Просмотр отчета
После прогона тестов откройте HTML-отчет:

bash
npm run test:report

🐞 Найденные баги (автотестами)
Ложный успех при ошибке 500: При падении бэкенда (500) интерфейс показывает зеленый тост «Рассылка успешно отправлена» (см. error-handling.spec.ts, REG-CORE-018).

Преждевременный успех: Тост об успехе появляется до завершения запроса (REG-CORE-013).

Отсутствие защиты от дублей: После успешной отправки форма не очищается, можно отправить повторно (REG-CORE-017).

Отсутствие предпросмотра: В интерфейсе OmniNotice отсутствует блок предпросмотра (Preview), хотя он заявлен в ТЗ (REG-CORE-010).

Отсутствие реального запроса: На мок-стенде кнопка «Отправить» показывает успех, но запрос в Network не уходит (REG-CORE-014, заскипан).

📝 Примечания
Тесты на историю, Telegram и payload заскипаны (.skip). После починки фронтенда/бэкенда — убрать .skip и проверить.

API-тесты на идемпотентность закомментированы из-за блокера Doocot (403 Forbidden).
